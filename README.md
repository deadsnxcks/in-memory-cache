# In-Memory Cache

Потокобезопасный in-memory key-value кэш для Go с поддержкой времени жизни записей, автоматической фоновой очисткой и политикой вытеснения при достижении лимита памяти.

## Особенности реализации

* **Потокобезопасность:** Безопасное конкурентное использование из множества горутин.
* **TTL:** Каждая запись имеет индивидуальное время жизни. «Ленивое» удаление гарантирует, что протухшие данные никогда не будут возвращены клиенту.
* **Фоновая очистка:** Отдельная горутина периодически сканирует хранилище и удаляет истекшие записи, освобождая память.
* **Ограничение емкости:** Поддержка лимита элементов с умной политикой вытеснения за константное время O(1).

## Методы

### Публичные

* **Set(key string, value interface{}, ttl time.Duration)** - добавляет запись в кэш с указанным временем жизни. Если ключ уже существует, его значение и TTL обновляются.

* **Get(key string) (interface{}, bool)** - возвращает значение по ключу и флаг существования. Если запись протухла, возвращается `nil` и `false`.

* **Delete(key string)** - удаляет запись по ключу. Если ключ не существует, операция игнорируется.

* **Exists(key string) bool** - проверяет существование ключа в кэше. Возвращает `true`, если запись актуальна, иначе `false`.

* **Keys() []string** - возвращает срез всех актуальных ключей в кэше.

### Приватные

* **cleanup()** - фоновая горутина, которая периодически сканирует кэш и удаляет протухшие записи.

## Быстрый старт

```go
package main

import (
	"fmt"
	"time"

	"github.com/deadsnxcks/in-memory-cache/cache"
)

func main() {
	// Инициализация кэша:
	// - Фоновая очистка запускается каждые 5 секунд
	// - Максимальная вместимость: 1000 элементов (0 - без лимита)
	c := cache.New(5*time.Second, 1000)

	// Добавление значения с TTL 2 секунды
	c.Set("user_1", "Ignat", 2*time.Second)

	// Получение значения
	if val, ok := c.Get("user_1"); ok {
		fmt.Printf("Найдено: %v\n", val)
	}

	// Проверка существования ключа
	if c.Exists("user_1") {
		fmt.Println("Ключ все еще актуален")
	}

	// Ждем истечения TTL
	time.Sleep(3 * time.Second)

	// Данные автоматически инвалидированы
	if _, ok := c.Get("user_1"); !ok {
		fmt.Println("Время жизни ключа истекло, данные недоступны!")
	}
}
```

## Архитектурные решения

### Вытеснение при достижении MaxSize

Одной из проблем при реализации кэша с ограничением емкости является выбор способа вытеснения элементов при достижении лимита. Разобрав такие варианты как вытеснение случайного элемента, вытеснение наименее используемого (LRU) и вытеснение наименее недавно использованного (LFU), было принято решение использовать **рандомизированную выборку с учетом времени жизни**.

**Как это работает:**

Вместо того чтобы сканировать весь кэш, что долго и намертво блокирует работу других горутин, или строить сложные связные списки для классического LRU, что требует лишней памяти, алгоритм делает быстрый трюк:

1. При нехватке места кэш берет **5 случайных элементов**, благодаря псевдослучайной природе итерации по `map` в Go
2. Если среди них попадается уже "протухшая" запись (до которой еще не добрался фоновый воркер) - она удаляется, и место освобождается
3. Если протухших нет, алгоритм находит среди этой пятерки ту запись, чье время жизни истечет раньше остальных, и жертвует именно ей

**Преимущества такого подхода:**

* **Мгновенное выполнение O(1):** Алгоритм всегда делает максимум 5 проверок, независимо от того, лежит в кэше тысяча ключей или миллион. Мьютекс освобождается моментально, и кэш не становится узким местом под высокой нагрузкой.
* **Соответствие бизнес-логике:** Раз уж главная фишка нашего кэша - это TTL, логично удалять те данные, которые и так "умрут" быстрее всего.
* **Экономия ресурсов:** Нам не нужно хранить дополнительные счетчики обращений, указатели или двигать элементы в памяти, как это требуется в строгих реализациях LRU или LFU.
* **Прагматичность:** Математически доказано, что случайная выборка из нескольких элементов дает результат, очень близкий к идеальному, но без деградации производительности. Похожий подход используется в промышленных решениях, например, в Redis.
